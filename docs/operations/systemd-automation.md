# systemd user automation

**Status:** canonical
**Audience:** operators installing local user timers
**Owner:** `systemd/user/` and office-auto-lab maintainers
**Verified against:** pre-editorial parent-runtime hardening round

## Safety boundary

The tracked unit files are now **machine-neutral**. They do not contain a
checkout path or username. Each service reads one installed environment file:

```text
~/.config/office-auto-lab/runtime.env
```

That file records the exact checkout root, Python interpreter, and evidence
roots for the current operator. It is generated by the installer and is not
committed.

Do not hand-edit tracked unit files to point at another checkout. Re-run the
installer so the installed runtime identity remains explicit and reproducible.

## Render-only preflight

Before mutating a user systemd session, render the exact configuration into a
temporary directory:

```bash
PYTHONPATH=src python3 src/office_runtime/scripts/install_systemd.py render \
  --repo-root "$(pwd)" \
  --python-bin "$(command -v python3)" \
  --evidence-root "$HOME/repos" \
  --evidence-root "$HOME/Documents" \
  --out /tmp/office-systemd

systemd-analyze verify /tmp/office-systemd/units/*.service \
  /tmp/office-systemd/units/*.timer
```

The renderer fails if the checkout/Python/evidence roots are not absolute and
existing, if a required runtime script is missing, or if a tracked service still
contains a machine-specific `/home/matias/...` path or unresolved template
marker.

CI executes this render/verification path without touching a live user session.

## Installation

From the checkout that should own local Office automation:

```bash
PYTHONPATH=src python3 src/office_runtime/scripts/install_systemd.py install \
  --repo-root "$(pwd)" \
  --python-bin "$(pwd)/.venv/bin/python" \
  --evidence-root "$HOME/repos" \
  --evidence-root "$HOME/Documents" \
  --enable
```

Without `--enable`, the command installs/replaces the units and runtime
environment, reloads the user manager, and leaves timers disabled. This is the
preferred first install when credentials or artifact roots still need review.

With `--enable`, the installer enables and starts:

- `office-compile.timer`
- `staff-briefs.timer`
- `evidence-daily.timer`

Expected schedules remain: Office at 08:05/12:05/16:05/20:05, staff at
08:10/16:10, and evidence at 23:00, with persistent catch-up where declared by
the tracked timers.

## Runtime path

The services enter through one bounded routine adapter:

```text
systemd service
  -> runtime.env
  -> src/office_runtime/scripts/systemd_entrypoint.sh
  -> src/office_runtime/scripts/office_run.sh
  -> python -m office_runtime.cli ...
```

`office_run.sh` derives the repository root from its own location and uses the
configured `OFFICE_PYTHON`. The scheduled adapter accepts only the three declared
routines; an unknown routine fails instead of passing arbitrary shell commands.

Evidence roots are stored as a colon-separated list in `runtime.env`. The
installer rejects evidence paths containing `:` so parsing is unambiguous.

## Verification

```bash
systemctl --user list-timers --all
systemctl --user status office-compile.timer staff-briefs.timer evidence-daily.timer
journalctl --user -u office-compile.service -n 50 --no-pager
cat ~/.config/office-auto-lab/runtime.env
```

Reconcile service exit status with domain artifacts: Office manifest/latest,
staff indexes, or evidence JSONL. The wrapper preserves child exit codes and
writes local logs, but neither a green timer nor a green syntax check proves
artifact correctness.

## Upgrade

After moving the checkout, changing virtual environments, or changing evidence
roots, re-run the same `install` command with the new absolute values. The
installer replaces the tracked units/configuration and reloads the user manager.
There is no second hand-maintained unit copy.

## Uninstall

```bash
PYTHONPATH=src python3 src/office_runtime/scripts/install_systemd.py uninstall
```

This disables the tracked timers, removes the installed units, and reloads the
user manager. Add `--purge-config` to also remove
`~/.config/office-auto-lab/runtime.env`.

## Recovery

On failure, stop the affected timer, inspect the journal plus runtime
logs/artifacts, correct the dependency/profile or installed runtime configuration,
re-run `install` without `--enable`, and manually start the affected service once
before re-enabling timers.

Stop if paths, credentials, Python environment, or artifact ownership are
ambiguous. See [failure recovery](failure-recovery.md).
