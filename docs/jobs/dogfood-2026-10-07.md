# Job Search vertical dogfood — 2026-10-07

## Objective

Make an active job opportunity cheap to act on: current process state, verified contact/channel, required materials, next block, stop condition, and due follow-up should be recoverable without repeated archaeology.

## Authority composition

The dogfood preserved these owners:

- Projects Job Search Agenda / Context MCP: governed orientation and bounded frontier;
- ATS 2026 `Current`: canonical application/process state;
- ATS 2026 `Assets`: human-owned application-asset identity/readiness;
- Gmail: process communication evidence;
- Google Calendar: scheduled next-stage evidence;
- CRM/PERSONAS: canonical relationship state;
- Google Contacts: address-book evidence only, never enough by matching name alone;
- Drive: file storage/content, not authority for which application asset is approved-current;
- Office jobs SIDECAR: deterministic composition only.

## Contact-resolution finding

Google Contacts can contain same-name people tied to unrelated companies. Therefore a contact is accepted only with process/organization evidence. Current recruiter contacts were not found in canonical CRM/PERSONAS, which is acceptable: process-scoped contacts can be used without silently promoting them into relationship truth.

Bounded resolution order for an unresolved but useful person:

1. exact ATS source-contact + company/process in recent Gmail;
2. exact CRM/PERSONAS identity;
3. Contacts only with organization/process disambiguation;
4. official company recruiting/team source;
5. stop rather than invent a warm path.

## Application-asset finding

Drive search was too noisy to answer 'which CV/template is current?'. Inspection found:

- `CV_IGLESIAS.pdf`: useful English Data/AI base, but not safe to auto-promote universally;
- `Cover Letter Template — Reference`: historical, company-specific reference, not a sendable generic template;
- no approved role-family base was discoverable for Data & AI Engineering, Data Science / Applied ML, or institutional consulting;
- no reusable financial-proposal template was established.

Dogfood therefore created a native `Assets` table inside the existing ATS workbook instead of another job database. Initial state is deliberately truthful:

- generic CV -> `candidate_needs_review`;
- cover-letter document -> `reference_only`;
- three role-family CV bases -> `missing`;
- financial-proposal template -> `missing`.

`artifact:ops.job-application-prep@1` converts those states into `approved`, `review-required`, `draft-from-reference`, `missing-known`, or `missing-unregistered`. Only all-`approved` requirements produce material submission readiness.

## What is now cheap

For an active ATS row the system can now deterministically separate:

- apply now;
- prepare application;
- follow up;
- wait because already scheduled;
- close/wait after rejection;
- verified process contact vs organization channel vs unresolved contact vs contact not needed;
- approved application asset vs candidate/reference/missing asset;
- new actionable attention vs unchanged repeated state.

## Deliberate stop boundaries

Do not automatically:

- submit applications;
- send recruiter messages;
- mutate ATS process state;
- create/accept Calendar commitments;
- add every recruiter to CRM;
- treat a same-name address as the right person;
- promote generated or historical CV/letter content to `approved_current`.
